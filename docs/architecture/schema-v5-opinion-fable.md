# Q9 design review — Fable 5.1, independent seat

**Verdict: sound with changes.** C4 is the right family and the candidate analysis is fair. Three things must change before the PR: the classification rule should partition by **dpkg ownership of the effective file**, not by directory (F1); the detector must enumerate through the manager and treat aliases, `.wants/` symlinks, masks and drop-ins explicitly, or it both fails open on aliases and drowns in false extras (F2); and the new tombstone rule must cover every coverage, because the adapter actuates tombstones coverage-blind and a `sshd.service` tombstone already passes v4 lint today (F3). The rest are migration gaps and tightenings.

What I verified by reading (no execution): every `file:line` in F.1 of the design that I cite below resolves to what the design says it does, except where a finding says otherwise. I traced the regexes by hand; I did not run them.

## Findings

**F1 (High) — partition by ownership, not by directory.** `C.3` steps 3–5 decide the tier by *where* the effective file sits. That proxy has a hole the design cannot close: a dpkg-owned unit or drop-in outside `/usr/lib/systemd/system` (a conffile unit under `/etc/systemd/system`, a package-shipped `/etc/systemd/system/<x>.d/*.conf`) is "anywhere else", so it is matched against name claims — and the design removes `dpkg` from the name enum, so it has **no legal spelling** and is permanently extra. Replace the partition: *for each effective file, if dpkg owns it the unit is in the package tier (clean iff every owning package is declared in `unit-package`); otherwise it is in the name tier.* Each file has one owner set, so "exactly one claim type applies" still holds, rule 5 disappears, and removing `dpkg` from the name enum stays correct. Proposed text for `C.3` step 3: "**Ownership decides the tier.** Query dpkg for the effective file (both the `/lib` and `/usr/lib` spellings, or read `/var/lib/dpkg/info/*.list` directly, which also handles multiple owners without parsing `dpkg -S`). Owned: clean only if every owning package is declared in `unit-package`. Unowned: match against `unit-writer`." Delete step 5. Add to F.3: "`dpkg -S /etc/systemd/system/* /etc/systemd/system/*.d/*` on pastebin — any hit is a file this design must be able to describe."

**F2 (High) — enumeration and the four non-fragment file kinds.** `C.3` step 1 "enumerate unit files" is ambiguous and step 2 "an alias counts once as `ssh.service`" is unsafe as written.
- On every Debian host with sshd enabled, `/etc/systemd/system/sshd.service` is a symlink to the vendor `ssh.service`, created by the postinst (`Alias=`); likewise `dbus-org.freedesktop.login1.service`, `syslog.service`, `ctrl-alt-del.target`. Enabling also creates `/etc/systemd/system/*.wants/<unit>` symlinks for every enabled unit, vendor ones included. A directory walk of `/etc` reports all of these as extras; a walk that follows symlinks to "resolve the effective file" instead absolves a rogue `/etc/systemd/system/evil.service -> /usr/lib/systemd/system/ssh.service` by collapsing it into `ssh.service` (fail-open).
- Proposed text: "**Enumerate through the manager, never by walking directories**: `systemctl list-unit-files` and `list-units` for the four types, then per unit `Id`, `Names`, `FragmentPath`, `SourcePath`, `DropInPaths`, `LoadState`, `UnitFileState`. `.wants/` and `.requires/` entries are dependencies, not units, and are never classified. **An alias symlink is clean only if its name appears in the target fragment's `[Install] Alias=`;** any other name in `Names` is extra. A mask (`UnitFileState=masked`) and each `DropInPaths` entry is a file classified on its own under F1. A generated unit (`UnitFileState=generated`) is classified by its `SourcePath` (Debian's sysv-generator units then land in the package tier when `/etc/init.d/<x>` is owned). A transient unit has no file; see E2. If `systemctl` cannot reach a manager (`/run/systemd/system` absent) the detector reports *unverifiable* and classifies nothing as clean." This also answers the brief's "what the device can and cannot verify": it can verify ownership, alias legitimacy and the file set; it cannot verify integrity or intent.

**F3 (High) — the tombstone rule must not be comprehensive-only, and it is needed today.** Design §A.4 says the hazard appears "once `ssh.service` is declarable". It is live now: `service_map` ids already admit `sshd.service` (`schema/goal-file.schema.json:335`), the comprehensive-domain rule reads present services only (`bin/schema_lint.py:1536`, `:1578-1599`), and the adapter's teardown is gated on neither coverage nor writer (`policy/tendcf_services.cf:240-245`, `:275-278`): `fileexists("/etc/systemd/system/sshd.service")` is true on Debian (the alias symlink), so a v4 goal file with `"sshd.service": {"state":"absent"}` in `supervision` passes lint and runs `systemctl disable --now sshd.service` on pastebin. D.2's new rule limits itself to comprehensive domains; `supervision` with `not-yet-migrated` is still projected (`bin/projector.py:118-123`) and actuated. Proposed D.2 text: "Lint: every `state: absent` service in `supervision`, **in any coverage that admits entries**, must be covered (`covers()`) by a `unit-writer` key with `writer: cfengine`. Case 123 is the comprehensive instance; add 123b with coverage `not-yet-migrated`." `deploy/linux/canary/goal-file-absent.json` keeps `tendcf.canary.*` cfengine, so it passes. Also recommend, same PR or S0-style policy slice: at `policy/tendcf_services.cf:241` use `isplain()` rather than `fileexists()`, so teardown never deletes a symlink (alias or mask) it did not render.

**F4 (Medium) — the one-writer claim across kinds is declarative, not just classificatory.** `C.3` "Why this keeps one writer per unit" is true for the device's verdict and false for the file: a v5 goal file may carry `"ssh.service": {"writer":"cfengine"}` and `"openssh-server": {"writer":"dpkg"}` together, two writers declared for one name, and no lint can see it. That is a first in this design (D36, `architecture-DEFINITIVE-v3.md:188-190`). State it, and make the device report it: "A unit with files in both tiers is reported as `two-writers`, never clean, unless E5 admits the file kind." This is what makes E5/E6 one ruling (see table).

**F5 (Medium) — template keys should cover their instances.** Residue 4 is a defect with a two-line fix, not residue: a present `tendcf-worker@1.service` in a comprehensive domain is coverable only by a hyphen prefix, and `getty@*` is refused by the grammar. Define in C.2: `covers("X@.T", name)` is true iff `name == "X@.T"` or `name` matches `X@<nonempty>.T`; overlap of a template key with a prefix uses the template's `X@` as its prefix. Add case 117b (template key under a prefix that covers it) and a happy row (template key plus an instance service).

**F6 (Medium) — detector scope across domains is unstated.** `C.3` says "domain `supervision`", but `unit-writer` entries may sit in any state domain (case 98's `packaging`, `:1566` overlap is global) and `unit-package` ids are unique across domains (case 131). Proposed text: "The host has one unit namespace. Detection runs iff `supervision` is `comprehensive`; the registry it reads is the **union** of every domain's `unit-writer` and `unit-package` entries; `coverage` on other domains does not switch it on or off."

**F7 (Medium) — one regex, not `anyOf`.** The design's `propertyNames` `anyOf` turns case 35 (`com.tendcf.caddy`, `examples/broken/35-malformed-writer-prefix/goal-file.json:90`, README `schema (`pattern`)` at `:83`) into an `anyOf` failure; whether the lint's evidence set still carries `pattern` through `anyOf` context is unverified, and it forces 113–116 onto the weaker `propertyNames` token. One pattern keeps "one spelling" and the existing precedent:
```
"pattern": "^[A-Za-z0-9](?:[A-Za-z0-9._-]*@?\\.(?:service|socket|timer|path)|[A-Za-z0-9._-]+[.-]\\*)$"
```
The `+` in the prefix branch replaces `minLength: 4` (`ab.*` is the shortest). Traced: accepts `ssh.service`, `sshd@.service`, `dbus-org.freedesktop.login1.service`, `tendcf-execd.service`, `systemd-*`, `tendcf.canary.*`, `com.tendcf.caddy.*`; rejects `*`, `ssh*`, `ssh*.service`, `getty@tty1.service`, `com.tendcf.caddy`, `foo.target`.

**F8 (Medium) — migration gaps.** D.2 omits: `EXPECTED_PROJECTION` 27→28 (`bin/schema_lint.py:89`; case 132 lives in `broken-projection/`); the `nix2cf` `GOAL_FILE_SCHEMA_VERSION` const and its CI check (reconciliation `:290`); `linux-targets.md:36` row-4 note for v5; `check.py:34-37` comment, which will name `unit-package` among the non-projecting kinds; the projector's prose list at `bin/projector.py:434-438` (design says `:436`, right place); case 35's README cell (F7); a `schema_lint.py` self-check for the overlap truth table — there is no `tests/**/*.py` harness in this repo, so D.4 item 3 has nowhere to run unless it joins the in-lint property tests at `:1922-1947`.

**F9 (Low) — missing negative cases.** (a) exact key with a non-code suffix `foo.target` → `pattern`; (b) `unit-package` entry with an extra key → `additionalProperties`, and without `writer` → `required` (precedent: 110–112 added for the same shape on `supervisor`); (c) 123b (F3); (d) 117b (F5). Case 122 is a variant of existing case 64 (`README.md:261`), not a new rule; keep it but label it a regression of `covers()` on exact keys, and note it would not catch a regression to `startswith` (equality satisfies both).

**F10 (Low) — `unit-package` semantics to state in its description.** (a) A declared package that is not installed is not a finding (detector data, like a prefix with no units). (b) `state: present` means the claim is present, not the package. (c) The id is a binary package name; the detector compares against the owning *binary* package, so `systemd` units split across `systemd`, `udev`, `systemd-timesyncd`, `systemd-resolved` etc. need each named — C.4 reason 3's "small" count should say this. (d) `extra_entries` is a counter only (`schema/report-row.schema.json:86-90`); the "unverifiable" reason in C.3 step 6 needs a report-row field or a log line — say which.

## Strongest case against C4 (brief item 2)

The signed consent object's meaning now depends on an unsigned, root-writable local database: two devices with the same goal file have different covered sets. On a general-purpose host `extra_entries` will be chronically non-zero after any `apt install`, and the skew signal C.4 reason 1 prizes becomes alarm noise. And `unit-package` is an ownership axis, not a prefix, so "comprehensive" quietly comes to mean "described by name or by ownership" — say so in `state_entries`' description. None of this outweighs C2′'s silent fail-open or C3's file-list churn; it is the price, and report-only plus a fixed-role host makes it payable.
